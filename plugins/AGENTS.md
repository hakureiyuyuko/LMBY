# plugins/ —— 外部插件的落脚地

> 这份是给**在这里写代码的 agent** 看的规范。你要做的插件**不是 LMBY 主程序的一部分**。

## 0. 先对齐一件事：LMBY 没有插件系统，这是刻意的

`docs/REQUIREMENTS.md` 的「不做」清单里明确列着**插件系统**；
`docs/ROADMAP.md` 的三条纪律里也写着「不做超出需求的抽象。Emby 的『重』
很大部分来自插件系统与通用框架 —— LMBY 只要够用的接口」。

所以**别指望在内核里挂 hook**。这里的「插件」= **独立进程 / 静态资源**，
只通过 LMBY 已经公开的接口跟它对接。

这么定不只是架构洁癖，更是为了你自己好：主程序还在快速演进，
**这个仓库有多个 agent 在并行改**——你读到的代码可能已经不是你上次读到的那份，
贴着内核写的东西一改主线就碎，而你没有主线的上下文。

### 插件可以依赖什么

| 可以 | 不可以 |
|---|---|
| `HTTP /api/v1/...`（清单见 `docs/API.md`） | `import` 任何 `internal/...` 包 |
| 只读读取 `/etc/lmby/config.toml`（坐标见 `docs/local-*.md`） | 改 `internal/` `cmd/` `migrations/` `web/src/` |
| 自己的语言、依赖、构建方式 | 往 `go.mod` 加依赖、改 `.github/workflows/` |
| 数据库**只读**查询（确有必要时） | 直接写 LMBY 的表 —— 会破坏扫描器/迁移的不变量 |

**需要内核配合怎么办**：那是一次**核心改动**，不属于插件。单独提，说明「现有 API
为什么不够」，按下面 §2 的规矩在 `dev` 上走完整验证。不要为了插件方便去改内核接口。

## 0.5 你其实在一个**实验分支**上

这个插件是以「fork 一份分支出来做实验」的方式做的 —— 目标**不是**「必须合进主线的功能」，
而是**可以随时整个丢掉**的实验。这条直接决定分支纪律：

- **从 `dev` fork，不要从 `main`**。`main` 是发布态，交付面被 `strip-ui-notes.py` 剥离过，
  拿它当基线会莫名其妙地少东西。
- 分支名建议 `plugin/<名字>`，**一个插件一个分支**。
- **分支里只动 `plugins/<名字>/`。**
- 定期 `git rebase dev` 把它跟上，别让它烂在那儿。

### 为什么「只动自己目录」在这里比平时更重要

实验分支的价值全在**丢弃成本**上。只要核心文件一行没碰：

| 你想做的事 | 结果 |
|---|---|
| 跟主线 | `git rebase dev` 不会冲突 |
| 合进去 | 只提 `plugins/<名字>/` 那一部分就行 |
| 放弃 | `git branch -D` 完事，零代价 |

**碰了 `internal/` 或 `web/src/`，上面三件事立刻都变手工活。**
所以哪怕实验期「只是想临时改一下接口」，也先停下来 —— 那是核心改动，
按 §2 单独提（见本文件末尾「需要内核配合怎么办」）。

实验分支里别的都可以放肆：换语言、加依赖、随便写。唯一不变的是
**共享文件上的规矩照旧**（别写内网坐标、别提交密钥）—— 因为分支随时可能被合回来。

## 1. 目录约定

```
plugins/
  AGENTS.md          ← 本文件（规范）
  README.md          ← 给人看的入口
  <插件名>/           ← 一个插件一个目录，小写 + 连字符
    README.md        ← 它做什么、怎么装、怎么跑、依赖哪些接口（哪个版本验证过）
    NOTES.md         ← 你做的假设、不确定的地方（见 §6）
    ...              ← 你自己的结构，随意
```

- 一个插件一个目录，**不许跨目录互相引用**。
- 每个插件必须**自包含**：`cd plugins/<名字> && <它自己的构建命令>` 就能起来。
- 不要提交构建产物、依赖缓存、密钥。

## 2. 仓库硬规矩（继承主仓库，不另行商量）

1. **所有开发在 `dev`**。`main` 只在发版时合并；**不要自己发版、不要打 tag、不要动 `main`**。
2. **不提交没真跑验证的改动**。插件同样：给出「怎么验证」的可复现命令 + 它真跑过的输出。
3. **公开文档里不写内网坐标**（IP、域名、凭据）。要写就写进 `docs/local-*.md`（已 gitignore）。
   本文件会进 git，所以这里也不会出现地址。
4. 不提交密钥。
5. 许可证 **AGPL-3.0**：第三方代码只能「读思路」，不能整段抄
   （Jellyfin 是 GPL-2.0，与本项目不兼容）。
6. commit 信息用中文，说清**为什么**（不是「改了什么」），并带 trailer：
   `Co-authored-by: Chatbox <chatbox@chatboxai.com>`
7. 提交前 `git status` 自查：**只应出现你自己目录下的文件**。手滑改到核心是最常见的翻车。

## 3. 环境与工具链速查

- Go 1.27.1（在 `~/.local/go/bin`）、`CGO_ENABLED=0`、`GOFLAGS=-mod=mod`；Node v22。
- 跑着的实例坐标、账号、挂载方式：见 `docs/local-notes.md` / `docs/local-handoff.md`（gitignored）。
- **实测踩过的坑**（别重踩）：
  - `web/dist/index.html` 入库的是**占位页**。`go build` 之前不先 `npm run build`，
    会把一个「前端未构建」的空壳烤进二进制 —— 后端接口全正常，只有首页是坏的。
  - `go test -race` 需要 CGO，而本仓库 `CGO_ENABLED=0` ⇒ 跑不了。用 `go test ./...`。
  - `golangci-lint` 钉在 **v2.13.2**（`.golangci.yml` 是 v2 格式），别用 `latest`。
  - 媒体库在 rclone（网盘）上：**小文件冷读 2~10 秒**，别拿它当性能基线。
  - 探测队列可能积压几千个文件 ⇒ **未探测完的文件「不可播」**（起播接口不给会话 id）。
  - 容器 `/tmp` 是 2G tmpfs，跑界面测试前清干净。

## 4. 如果你要用 LMBY 的接口

- 先读 `docs/API.md`，**再读当前代码**——**以代码为准**，文档可能滞后。
- 只依赖你**真跑过**的接口，别照文档猜字段名。跑不通就说明你的假设错了，去改假设。
- 接口会变（这仓库在快速迭代）：
  - 解析响应要**宽容**（字段缺失/多出来别崩）；
  - 在插件 README 里写清楚「依赖哪些接口、在哪个版本上验证过」。

## 5. 验证与提交

- 验收方式你自己定，但必须是**可复现的命令**，写进插件的 README。
- 改动只落在自己的目录里，与主线冲突概率最小。
- 需要核心配合的改动：**单独提交、单独说明、单独验证**，不要混在插件提交里。

## 6. 不确定就写下来

你没有主线的完整上下文。凡是「我假设……」「这里依赖了内核的 X 行为……」
「我没验证过 Y……」，都写进 `plugins/<名字>/NOTES.md`。

**写下假设比假设正确更有用** —— 主线的人扫一眼就能判断要不要配合你。
