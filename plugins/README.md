# plugins/

LMBY 的**外部插件**落脚地。

## 先读这个

**LMBY 没有（也不打算有）进程内插件系统** —— `docs/REQUIREMENTS.md` 的「不做」清单里
明确列着插件系统，`docs/ROADMAP.md` 的纪律也写着「不做超出需求的抽象」。
所以这里的「插件」是**独立于主程序的进程 / 静态资源**，只通过 LMBY 公开的 HTTP 接口
跟它对接，**不往内核里加 hook**。

这么定还有个现实原因：主程序还在快速演进、有多个 agent 并行在改，
贴着内核写的插件会被主线改动打碎。

这个插件是**以实验分支的形式**在做的：从 `dev` fork 一份 `plugin/<名字>` 出来，
目标是「**随时可以整个丢掉**」的实验。所以纪律是 **分支里只动 `plugins/<名字>/`** ——
碰了核心文件，rebase、合入、丢弃这三件事就都变手工活了（详见 AGENTS.md §0.5）。

👉 **在这里动手之前，先读 [`AGENTS.md`](./AGENTS.md)** —— 那是给写代码的 agent 看的规范
（目录约定、仓库硬规矩、可以依赖什么、环境里实测踩过的坑）。

## 目录

一个插件一个目录：

```
plugins/
  AGENTS.md         开发规范（agent 必读）
  README.md         本文件
  <插件名>/
    README.md       它做什么、怎么装、怎么跑、依赖哪些接口（在哪个版本上验证过）
    NOTES.md        你做的假设与不确定的地方
```

## 需要内核配合怎么办

那属于**核心改动**，不是插件的一部分。单独提、单独验证，说明「现有接口为什么不够」——
不要为了插件方便去改 `internal/`。
