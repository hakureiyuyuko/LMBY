## 四、条目身份：不能用「会被元数据改写」的字段

### 症状

同一部作品在库里出现 2~3 份，多出来的那份通常**没有文件**（集没有标题、点了放不了）。
106 上实测：`公主连结！ReDive` 有三份（`Re:Dive` / `Re：Dive` / `ReDive`）、
`战姬绝唱` 与 `战姬绝唱Symphogear`、`沙漠大冒险`（目录 2023 / 条目 2024）……

### 根因

条目身份原本是 `(库, 类型, lower(标题), coalesce(year,0))`，而**标题与年份都会被
nfo / 刮削改写**（`internal/store/items.go` 的 `applyItemMetaSQL`：`title`、`year` 都在它手里，
`locked_fields` 只保护人工改过的字段）。扫描器却是拿**目录名解析出来的标题**去查的：

- nfo 的标题与目录名不同（加英文副标题、全角冒号、词序不同、译名不同）→ 查不到自己；
- 年份被 nfo 改成首播年 → 同样查不到。

**触发条件只需要「给已有剧集加一个文件」**，不需要任何故障：

```
handleVideo（路径不在增量状态里）→ ensureItem → ensureDedup（目录名解析出的标题 + 年份）
   → FindSeriesID 查不到（标题/年份已被元数据改写）→ InsertItem 造一份新的
   → 新文件挂到新那份上；带路径的那份留在原地
```

掉盘那次的后果更重：整库软删 → 每轮重扫都把 38k 个文件当「新文件」→ 一次性造出几十个
重复剧集 + 几百个空壳集（那些文件插不进去，`path` 唯一约束还被墓碑占着）。

### 修法：给条目一个「扫描器专用身份」`scan_key`

迁移 `migrations/0019_item_scan_key.sql`：`media_items.scan_key text not null default ''`
+ 索引 `(library_id, kind, scan_key)`。

- 键的写法与扫描器内存里的去重键同构：`lower(标题) + '|' + 年份`，**由扫描器在建档时写入**；
- nfo / 刮削 / 人工编辑**一律不碰它** —— 这是整个修法的要点：身份与展示字段解耦。

查找顺序（`ensureDedup`，`internal/scanner/identity.go`）：

| 级别 | 条件 | 动作 |
|---|---|---|
| ① | `scan_key` 精确命中 | 直接用它（稳定，元数据怎么改都不影响） |
| ② | `(标题, 年份)` 精确命中 | 用它，并顺手补上 `scan_key`（兼容迁移前的老条目） |
| ③ | 同库同类型里**恰好一个**「标题相似 + 年份相容」且**还没有身份**的候选 | 认领它并补 `scan_key` |
| ④ | 都没有 | 新建（带着 `scan_key` 建） |

第 ③ 级的两个限制都是为了「宁可漏认也不错认」：候选唯一、候选不能已经有身份
（有身份说明它被别的目录认领过，是另一部）。相似判定见 `titleSimilar`
（归一化后相等 / 互为前后缀 / 词集相同，年份容许 ±5 年 —— nfo 改年份实测差 1~3 年）。

**回填**：`backfillScanKeys` 在每次扫描**遍历之前**跑，给还没有身份的剧集/电影补上身份 ——
用一个样本文件路径按建库时的同一套算法（`resolve` + `ParseVideo`）反推。可重入，
补完就没有了。必须在遍历前跑，否则第一轮仍按老键查、照样造重复。

**注意**：CJK 标题的相似度只能在 Go 里算 —— PostgreSQL 的 `[:alnum:]` 在 C.UTF-8 下不认
CJK，按「非字母数字」一刀切会把中文标题全抹成空串。

### 验收

`scripts/dev/verify-scan-identity.sh`（真库 + 真文件系统）：造一个「目录名 `某番 (2020)`、
tvshow.nfo 标题 `某番 完全版`」的剧集（身份漂移的触发条件），然后：

| 场景 | 期望 |
|---|---|
| 基线扫描 | 2 个剧集 / 4 集；nfo 的标题确实覆盖了目录名（前提成立） |
| **加一集再扫**（触发条件①） | 剧集数不变、`seriesNew=0`、新集挂在**原来那份**上 |
| **文件被软删又回来**（触发条件②） | 剧集数不变、文件被复活、没有问题记录 |

实例测量值（不是项目常量）：旧构建 `dev-8e8f77d` 跑同一脚本 **15 过 / 3 败**
（加一集就多出一份剧集），修后 **20 / 20**。
另：107 上换新构建后，库里 1445 个剧集 + 336 部电影的 `scan_key` 全部回填成功，
那一轮扫描 `seriesNew/moviesNew/newFiles` 全 0、问题 0。
