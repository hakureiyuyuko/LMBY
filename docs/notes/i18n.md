# 界面多语言（i18n）设计笔记

> 这篇记的是**取舍与真跑实测**。当前状态：基础设施完成、**浏览/播放路径已翻**，
> 管理页面还在翻译中（见文末覆盖率表）。

## 一、为什么「中文当源语言」

```ts
t('搜索')   // 键就是中文原文，英文目录里 '搜索': 'Search'
```

三个理由：

1. **代码与注释本来就是中文**，键用原文 diff 最小，也不用先发明一套键名（`nav.home`）再和原文对照；
2. **漏翻会退化成中文**（`t()` 找不到译文就返回原文）—— 用户至少看得懂，
   而看到 `detail.cast.title` 只会觉得产品坏了；
3. 加一门语言 = 加一份目录 + 一个 `Lang` 取值，没有别的改动。

不引 i18next / react-intl：这个项目的文案量用不上复数、性别、日期本地化那一套，
而多一个依赖就多一份体积与升级负担（前端是 `go:embed` 进二进制的）。

## 二、语言怎么定、怎么存

- 首次访问**探测一次**：`localStorage['lmby.lang']` → `navigator.language`（`zh*` → 中文，
  `en*` → English，其它语言先给中文，因为主用户群是中文用户）；
- 用户改过之后**以用户选择为准**（写 localStorage + 更新 `<html lang>`）；
- 选择器放在**顶栏**（与主题切换并排，都是「这台设备上的显示偏好」），
  **登录页右上角也有** —— 还没登录的人最需要它（他是谁、说什么语言都还不知道）。

## 三、后端保持语言中立

界面文案归界面，数据归数据。两个具体决定：

1. **首页各行的标题/副标题按 `key` 在客户端写**（`recommend` / `recent` / `favorites` / …），
   服务端给的中文只作兜底 —— 于是切语言不必重启服务，也不必给后端做双语数据。
2. **推荐依据用 API 返回的结构化数据在前面拼**：接口回 `taste`（流派+权重）、
   `sourceWorks`（看了几部）、`seedTitle`（最近看过哪部），
   界面据此写「因为你看过《X》」/「Because you watched “X”」。**文案不进 API。**

> 已知缺口（两处，都是「服务端给的文字」）：**报错文案**（如「列表不存在」）与
> **播放理由的正文**（如「视频是 10bit HEVC，浏览器解不了」）仍是中文 —— 它们由 Go 侧拼好返回，
> 界面只负责展示。彻底解决要么给后端加 message code，要么让前端按 code 自己写话，
> 属于 M7 做多语言时一并处理的事，记在 `docs/ROADMAP.md`。
> 彻底解决要么给后端加 message code，要么让前端按 HTTP 状态码自己写话 ——
> 属于 M7 做多语言时一并处理的事，记在 `docs/ROADMAP.md`。

## 四、把「漏翻」变成可测量的

i18n 最怕的不是翻错，而是**漏翻**：某个按钮在英文界面里还是中文，只有用户撞上才发现。
所以有两个工具：

| 工具 | 干什么 |
|---|---|
| `scripts/dev/i18n-coverage.mjs` | 静态扫源码，数「没包 `t(...)` 的界面文案」；`--max N` 可当预算守住 |
| 同一工具的第二项检查 | 数「**用了 `t(...)` 但英文目录里没有这条**」—— 这类最阴险：`t()` 会静默退化成中文，看上去像漏包、实际是漏写目录（真踩到：`t('选择媒体库')` 包了但没翻，页面还是中文） |
| `scripts/dev/i18n-ui-test.mjs` | 界面侧证明「翻了的确实生效、切换链路真的通」（见下） |

覆盖率工具还会报「目录里有、但没人用」的键（提示，不报错）—— 里面有一部分是
**给还没接的页面预备的**（详情页/播放器），以及 `media.ts` / `people.ts` 里
**用变量查表**的键（`t(key)`，静态扫不到）。

## 六、覆盖率现状（实测）

```
node scripts/dev/i18n-coverage.mjs
```

- **已翻**：顶栏与导航、登录页、首页、搜索页与联想、海报墙（墙 + 媒体库选择页）、
  我的列表与列表详情、**详情页、播放器**，以及 `media.ts`（类型名）、`people.ts`（角色名）、
  `capabilities.ts`（播放方式与流动作标签）三处公共文案。
  → **看片这条路径（首页 → 海报墙 → 详情 → 播放）整条是英文了**。
- **待翻 486 条 / 20 个文件**：全是管理面（库管理、条目编辑、人工匹配、直播电视、设置、会话、个人中心）。

## 七、这一轮踩的坑

1. **裸中文键能编译，但是个陷阱**：CJK 是合法的 JS 标识符字符，所以 `搜索: 'Search'`
   能过编译器；可 `正在加载…: 'Loading…'` 这种带 `…` 的键直接语法错误
   （而 `…` 恰好是中文文案里最常见的字符之一）。统一加引号，并让工具两种都认。
2. **测试会依赖「环境默认语言」**：i18n 一上线，headless Chrome（`navigator.language=en-US`）
   里所有断言中文的界面测试一起假失败。修法是测试里**显式钉死语言**：
   `localStorage.setItem('lmby.lang','zh-CN')` + reload。
   ⚠️ `Emulation.setLocaleOverride` **在这里没用** —— 它在部分 Chrome 上只影响 `Intl`，
   不改 `navigator.language`（实测无效，白折腾了一轮）。
3. **别拿 aria-label / 文本当测试选择器**：我把轮播箭头的 `aria-label` 从「下一部」
   改成「轮播下一部」（顺手更清楚），当场打断了一条断言。
   稳定的钩子应该是 `data-*`（本项目已经在用 `data-facet` / `data-hero-dot` 那一套）。
4. **同一件事要能在工具里量出来**：这一轮定的两个工具（覆盖率、缺失译文）
   都是被真问题逼出来的 —— 「测不到的东西就会悄悄坏」。
