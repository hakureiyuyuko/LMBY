# LMBY v1.0.4 —— 国庆特别更新：字幕能选了，封面也回来了

这次是两个「看着像坏了，其实是没接上」的问题：**外挂字幕一条都选不到**，
以及**继续观看那排卡片只有灰底、没有封面**。另外顺手修好了本地宽幅图被漏掉的老毛病。

> 本版**新增迁移 0020**：新表 `subtitles`（外挂字幕与视频的关联）。
> 纯增量、不动现有数据，首次启动自动执行；装上二进制重启即可。
> HTTP 接口与配置文件键没有破坏性改动。

## 一、外挂字幕与视频的关联（新）

**症状**：目录里每集都配了 `.chs.ass`，可播放器上**一条字幕都选不到** ——
既没有内嵌的，也没有外挂的。

**原因**：扫描器从 M1 起就认识外挂字幕（`parser.IsSubtitle`），但那个分支只做了
一次计数（`w.stats.Subtitles++`）：**不建条目、不建关联**。于是库里 22714 个字幕
文件，一条都没进数据库。这是一笔一直挂在路线图上的账（原本排在 M1，后推到 M2）。

**本版做法**，目标是**播放器一行都不用改**：

| 环节 | 做法 |
|---|---|
| 扫描 | 按**完整视频主干**前缀匹配归属，落新表 `subtitles`。候选视频按主干**从长到短**试 —— 视频名自己可能带点号（真实语料 `SSSS.古立特宇宙 (2023).chs.ass`），短名会抢走长名的字幕 |
| 播放 | 外挂字幕当成**合成轨道**接在内嵌流后面，序号从 **1000** 起。界面照旧用 `subtitleStreamIndex` 选轨道、照旧走 `/api/v1/play/{sid}/subtitles/{序号}.{后缀}`，服务端在取的时候按序号分流 |
| 下发 | `ass`/`ssa` 原样交给前端 libass（保留特效与排版）；`srt` 转 WebVTT；非 UTF-8 先转 UTF-8 |

语言与格式从文件名解析，例如 `S01E01.chs.ass` → 语言 `chs`、格式 `ass`；
`S01E01.zh-CN.简体&繁体.ass` → 语言 `zh-CN`、标题「简体&繁体」。
语言表是按真实语料建的：从媒体库抓了 **13278 个**外挂字幕文件名，
其中 **99.9% 是 `<集名>.chs.ass`**，其余是 `cht` / `chi` / `zh` / `zh-CN`。

**本版只收文本格式**（`ass` / `ssa` / `srt` / `vtt`）。位图字幕（`sup`/`sub`/`idx`）
要烧录才能看，仍只计数，留到后面的版本。

**编码**这一环踩了个坑值得记一笔：ffmpeg 的 **ass 解复用器只认 UTF-8** ——
喂它 GB18030 的 `.ass` 会在**打开输入**时就失败（实测 exit 183 / Invalid data found），
`-sub_charenc` 只对 `srt` 那类纯文本字幕生效。所以编码转换走 `iconv`
（来自 `libc-bin`，Debian 必装）。

**升级须知**：关联是**扫描时**写进去的，所以升级后需要**重扫一次该库**
才会看到字幕（第一次是全量遍历，按经验比较久；之后是增量的）。

## 二、剧集没有封面时，回落到所属剧

**症状**：首页「继续观看」那排卡片全是灰底、没有封面。

**原因**：那排卡片放的是**剧集**，卡片要的是竖版海报（`kind=poster`），
而扫描器给剧集写的只有 16:9 的 `-thumb.jpg` —— 海报只写在剧身上。
于是每次都是本地不命中 → 回源元数据源 → 拿不到 → 前端把图藏起来，只剩灰底。

**本版做法**：在取图顺序里，本地未命中之后、回源之前，插一层**回落到所属剧**：

```
剧集要 poster / fanart / backdrop / banner / logo  → 落到所属剧的同类图
剧集要 thumb                                        → 不回落
```

`thumb` 故意不回落 —— 那是剧集自己的截图，拿剧的海报顶上只会误导；
前端在 `thumb` 取不到时会自己退到 `poster`，那条路现在也通了。

## 三、本地宽幅图不再被漏掉

**症状**：明明有 `fanart.jpg`，界面还是回源；首页 hero 与详情页背景只能退回竖版海报。

**原因**：扫描器把宽幅图（`fanart.jpg` / `backdrop.jpg` / …）一律登记成
`kind=fanart`，而界面请求的是 `kind=backdrop`。取图按「严格相等」匹配 kind，
两边名字不一致 → 本地那张永远命不中。

**本版做法**：取图按**候选 kind** 匹配，`fanart ↔ backdrop` 互为别名。
优先级顺序没变（来源仍然是第一位：本地 > 手选 > 远程），所以本地图依旧压过远程图。

## 四、验收（真跑）

| 场景 | 结果 |
|---|---|
| 外挂字幕（真实验例：一条已探测的真实剧集 + 库里的真 `.ass`） | ① UTF-8 `ass` 下发后与磁盘源文件**逐字节一致**；② 同一文件转成 GB18030，经 iconv 转回后与 ① 逐字节一致（中文没乱码）；③ `srt` → WEBVTT，时间戳逗号变点、正文逗号与中文完好 |
| 字幕验收脚本（自造素材扫描 + 借真实条目验下发） | **13 过 / 0 败** |
| 剧集封面回落（条目 7795「这里⇔那里」，其剧 7793） | 剧集要 `poster`/`backdrop` → 200，与剧身同尺寸图**逐字节一致**；要 `thumb` → 仍是它自己那张 |
| 宽幅图别名 | 同一份数据只换二进制：官方 v1.0.3 `backdrop` **404** → 本版 **200**（与 `fanart` 返回同一张图）；验收脚本 v1.0.3 **13 过 / 3 败** → 本版 **16 过 / 0 败** |
| 单测 / 前后端 | `go test ./...`、`go vet`、`golangci-lint` 0 issues、`check-scripts`、前端构建全绿 |

本版**没有界面改动**（不需要重新适配任何界面文案）。

## 五、说明

- 「继续观看」的封面、播放器的字幕轨道，都是**服务端**接上的，客户端不用升级；
  浏览器可能缓存了修复前的 404，硬刷一次（`Ctrl+Shift+R`）即可。
- 剧集封面回落的诊断结论：排查「图不显示」时，**先查那一条条目的 `images` 表里
  到底登记了哪几种 kind** —— 这类「请求方要的 kind，生产方没给这种条目写过」
  的问题这次一共遇到两回（另一回就是第三节的宽幅图别名）。
