# LMBY v0.3.0 —— M5 直播 / M6 界面完整化 / M7 用户与权限

LMBY 是**纯 Web 在线播放**的轻量自托管媒体服务器：浏览器是唯一客户端，HTTP 是唯一出口，
一个 Go 二进制（前端 `go:embed` 进去）+ PostgreSQL，**运行期零 Node**，AGPL-3.0。

> 这是 **1.0 之前的最后一个功能版本**。M5（直播电视）、M6（GUI 完整化）、M7（用户与权限地基）
> 都落在这一版里；之后是 M8（迁移 / 运维 / 发布）——那一步做完就是 1.0。
>
> 上一个 tag 是 v0.2.0（M4 转码与字幕）。从那时到现在的 52 个提交都算在这一版里。

## 一、直播电视（M5，完整落地）

- **直播源**：粘贴 / 上传 / 订阅地址三种导入；**定时刷新**（间隔属于源，可关）；
  按 url 去重，**刷新不动用户态**（停用 / 收藏 / 探测结果不会被覆盖）；删源不删频道。
- **频道探测**：真连一次源站（与播放**共用同一套输入参数**，避免「探得通却播不了」），
  写出人话摘要（如 `H.264 1920x1080 / MP2 立体声 48kHz（1.1s）`）与 `probe_ok` / `probe_at`；
  探测前先确认 `ffprobe` 真能跑，跑不了就**一条结果都不写**（绝不把「工具没装」写成「全部频道失效」）。
- **播放**：同一频道所有观众**共享一路 ffmpeg**；1 秒分片（实测起播 0.6~1.8 秒）；
  浏览器解不开的源编码（HEVC / MPEG-2）**自动转码**，Chrome 与 Safari 同看一台各走各的处理方式。
- **前台只列「能用能看的」**：探测过且失败的频道不出现（管理界面里仍在，能去修 / 能删源）。
- **起播失败 → 后台自动重探一次**（本版新增）：探通就保持可见并刷新快照，探不通就标记失效、
  前台不再显示。本地并发打满时**不重探**（那是本地资源问题，重探会把好频道标成失效），
  同一频道 60 秒只探一次，全程异步不占用用户的请求。
- **失败文案人话化**（本版新增）：起播失败回给界面的是「源站没有及时返回画面（这个频道可能已失效，
  我们已经自动重新探测过）」这种人话 + 一个可翻译的 `code`（`livetv_busy` /
  `livetv_source_timeout` / `livetv_failed`），原始 ffmpeg 错误照旧进日志。
- **外部播放器**：无状态签名 token（`/s/<token>/playlist.m3u`，带有效期），不需要登录。

## 二、界面完整化（M6）

- **首页**：大屏轮播 + 继续观看 + 我的收藏 + 为你推荐（按观看历史做流派画像，并说明推荐依据）
  + 评分最高 + 最近添加。
- **搜索**：PostgreSQL 函数 + STORED 生成列（中文二元组）+ ILIKE 兜底单字 + trigram 容忍错字；
  结果**分面**（类型 / 媒体库 / 流派 / 演职员）+ 即时联想。
- **详情页**：剧集 → 季 → 集、演职员、相关推荐；海报墙可按库浏览。
- **播放器**：多音轨 / 多字幕；ASS/SSA 交给前端 libass（保留定位与特效）、纯文本转 WebVTT 走原生轨道、
  图形字幕（PGS/VobSub）按需烧录；画质档；从上次位置续播。
- **我的列表**：收藏 + 播放列表 + 合集；**个人中心**：显示名、口令、外观、设备会话。
- **界面多语言**（中文 / English），CI 里有覆盖率守卫 —— 新增文案漏包 `t()` 会当场失败。
- **响应式**：手机上可用（导航、海报墙、详情、播放器都按窄屏排过）。
- **导航收窄**：库管理 / 人工匹配 / 会话 / 直播源 / 用户 全部收进「设置」，顶栏只留用户真正常用的入口。
- **媒体库「只读」**：只读库的元数据快照与刮削图片写进数据目录（`overlay/`），**不碰媒体目录**；
  有叠加层看板与一键清空。
- **扫描阈值可配**：默认「文件过小」阈值从 1 MiB 降到 64 KiB（这部实例上曾把 63 条正常短片当残片跳过），
  并可用 `[scan] min_file_size` 覆盖。

## 三、用户与权限（M7 地基）

- **库级可见性**：按用户勾选可见媒体库；不可见的库在**列表、搜索（含分面与联想）、首页四行、
  收藏、续看、条目详情（404）、起播**全部拦掉 —— 判定只有**一个入口**（`store.Viewer`）。
- **能力开关**：`allow_transcode`（不允许转码时，必须转码的片直接 403 且不起 ffmpeg）、
  `allow_livetv`（关掉后看不到「直播」入口）、**并发流上限**（0 = 用全局值）。
- **会话安全**：改口令 / 禁用 / 收紧库范围 → **立刻吊销该用户全部会话**；
  硬规则是「不能改自己的管理员与禁用位」「不能禁用 / 降级 / 删除**最后一个活跃管理员**」（服务端兜底）。
- **界面**：设置 → 用户（新建用户、按库授权、三个能力开关、重置口令、禁用、删除），
  界面上不出现「点了就 403」的入口（管理员位 / 禁用 / 删除对自己就是 disabled）。

## 四、这一版修掉的两个「上线才炸」的问题

1. **首页整页「读取首页失败」**：M7 把可见库过滤接进 SQL 之后，有两处**占位符与传参错位**
   （计数查询多传了 `limit/offset`、推荐那三段写了 `$4` 却只传 2~3 个参数）→ PostgreSQL 直接
   报 42P18。编译、`go vet`、单测**全都看不出来**（单测不连库），而且**管理员同样 500**
   （不限制的可见库是空数组，照样要过那几条 SQL）。现在修好了，并且把「十条读接口 × 两种视角」
   的断言加进验收；验收还会先给测试账号造一条观看记录，让「为你推荐」那三段真的跑起来。
2. **直播起播 502 的误诊**：那台起播 502 的频道**本来就是失效源**（`probe_ok=false`，
   前台根本不显示它 —— 是验收脚本按管理口径挑了列表第一条），ffmpeg 直测显示源站 302
   重定向到一个连不上的节点。**直播转码这条路本身是好的**（对探测能通的频道实测
   200 / 750ms、分片 `ffprobe` 为 h264 1920×1080）。顺手把上面两条（自动重探、文案人话化）做了。

## 六、已知限制（有意留着，不是漏了）

- **Safari / iOS**：原生 HLS / HEVC / WebVTT 的旁路代码就位，但**没有真机验证**。
- **直播**：失效源按探测快照判定 —— 起播失败会自动重探一次，但源站变坏总要先失败一次才被发现；
  没有回看 / 时移（滚动窗口只留最近 ~10 秒）；没有 EPG / 录制（二期）。
- 1 秒分片让请求数翻倍，弱网下表现未测；窗口大小目前是常量。
- **外链分享**（限次数 / 限有效期）与**审计日志**还是 M7 的待办；**家长分级**按计划推到二期。
- 个人中心还没有「字幕与音轨偏好」。
- 没有内置 TLS：要给家庭网络外访问请自己加反向代理。
- 图片/元数据**不写回媒体目录**（只读库用 `overlay/` 存放），这是有意设计。
- Windows / macOS 上不节流（无法暂停进程，优雅降级为「不节流」）。

## 七、快速开始

需要 PostgreSQL 与服务端 `ffmpeg`/`ffprobe`；配置放 `/etc/lmby/config.toml`，systemd 单元见 `deploy/`。
开发环境与从零搭建见 [`docs/DEV-ENV.md`](https://github.com/hakureiyuyuko/LMBY/blob/main/docs/DEV-ENV.md)。

**Assets**：`lmby-linux-amd64` / `lmby-linux-arm64` / `lmby-linux-armv7` / `lmby-windows-amd64.exe`，
以及 `SHA256SUMS.txt`（`sha256sum -c SHA256SUMS.txt` 校验）。
