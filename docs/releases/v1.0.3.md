# LMBY v1.0.3 —— 同一部作品不再被拆成好几份

修一个「会自己长出重复条目」的问题。它不需要任何故障就能触发，
而多出来的那份通常**没有文件** —— 界面上就是「集没标题、点了放不了」的重复卡片。

> 本版**新增迁移 0019**：`media_items` 加一列 `scan_key` + 索引。
> 纯增量、不动现有数据，首次启动自动执行；装上二进制重启即可。
> HTTP 接口与配置文件键没有破坏性改动。

---

## 一、症状与原因

**症状**（验证实例上的真实记录）：同一部作品在库里出现 2~3 份，例如

| 你看到的标题 | 其实是什么 |
|---|---|
| `公主连结！Re:Dive` | 本地 nfo 里的标题 |
| `公主连结！Re：Dive` | TMDB 抓来的标题（全角冒号） |
| `公主连结！ReDive` | 目录名解析出来的标题（没有冒号） |

类似还有 `战姬绝唱` 与 `战姬绝唱Symphogear`、`沙漠大冒险`（目录 `(2023)` /
条目里是 `2024`）。

**原因**：条目身份原本是 `(库, 类型, 标题, 年份)`，而**标题与年份都会被 nfo 与
刮削改写**（`locked_fields` 只保护你手工改过的字段）。扫描器却是拿**目录名解析出来的
标题**去查的 —— 一旦 nfo / TMDB 的写法与目录名不同，它下次就查不到自己，于是**新建
一份**；因为文件路径上还有唯一约束（归原来那份所有），新建的这份拿不到文件，就成了空壳。

**触发条件只需要「给已有剧集加一个文件」**（新一集、特典、补档）—— 不需要任何故障。
掉盘那次的连带损伤只是把它放大成了一次几十个。

## 二、本版怎么修

给条目加一个**扫描器专用身份**（`media_items.scan_key`）：建档时由扫描器写下
`lower(标题)|年份`，**nfo / 刮削 / 人工编辑一律不碰它** —— 身份与展示字段解耦。
查找按四级顺序：

| 级别 | 条件 | 动作 |
|---|---|---|
| ① | 扫描身份精确命中 | 直接用它（稳定，标题年份怎么改都不影响） |
| ② | `(标题, 年份)` 精确命中 | 用它，并顺手补上身份（兼容升级前的老条目） |
| ③ | 同库里**恰好一个**「标题相似 + 年份相容」且还没有身份的候选 | 认领它并补身份 |
| ④ | 都没有 | 新建（带上身份） |

升级后**第一次扫描会自动给老条目回填身份**（用文件路径按同一套解析反推），
之后就走第①级了。回填可重入，补完即止。

## 三、如果已经出现了重复条目

1. **升级后重扫一次该库**：老条目的身份会被回填，之后不会再产生新的重复；
2. 已经产生的那种**空壳条目不会自己消失**（它们没有文件，也不影响正常条目播放）。
   本版还没有「合并重复条目」的工具，需要清理时目前要在数据库层面处理；
   后续版本会考虑把这个整理动作做成运维工具。

## 四、验收（真跑）

| 场景 | 结果 |
|---|---|
| 新增验收脚本（造「目录名与 nfo 标题不同」的剧集，再逐条验证两种触发条件） | 旧构建 **15 过 / 3 败**（加一集就多出一份剧集、新集挂到空壳上）→ 修后 **20 / 20** |
| 迁移前的老库（1445 个剧集 / 38608 个文件）首次扫描 | 身份回填 **1445 / 1445**，`seriesNew=0`、`newFiles=0`、问题 **0**，文件数不变 |
| 迁移前的老库（336 部电影）首次扫描 | 身份回填 **336 / 336**，`moviesNew=0`，文件数不变 |
| 单测 | 身份串 / 标题归一化 / 相似度 / 认领判定（含「多个候选不认领」等边界） |
| 前后端 | `go test ./... -race`、`go vet`、`golangci-lint` 0 issues、`tsc`、`i18n` 守卫、`npm run build` 全绿 |

本版**没有界面改动**（不需要重新适配任何界面文案）。

## 五、其他（工程向，不影响使用）

- CI 的 lint 版本钉死为 `v2.13.2`：这台自建 runner 连 GitHub 的制品/缓存服务会
  「连上之后不再回数据」，`version: latest` 会让 lint 挂在 0% CPU 上六分钟后失败。
  钉死后 lint 13 秒通过，顺带让本地与 CI 用同一个版本，结果可复现。
- 发布脚本修正：第二次以后发版时，交付 README 的源文件会被合并判成「main 侧删除」，
  脚本现在会直接从 dev 取源 —— 不会再出现「交付分支上放着开发者 README」。
