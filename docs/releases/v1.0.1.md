# LMBY v1.0.1 —— 字幕修复与「检查更新」

1.0 之后的第一个补丁版。主要是修一处**会让人以为「字幕坏了」**的问题，
另加一个管理面小功能：在设置里查有没有新版本。

> 补丁版不含破坏性改动：HTTP 接口、配置文件键、数据库迁移都向前兼容。
> 本版**没有新增迁移**（schemaVersion 仍是 18），装上二进制重启即可。

---

## 一、字幕（本次重点）

三个问题都是**看片时才会遇到、但遇到了就整片没法看**的那类：

- **自动选轨永远选不出字幕。** 原实现要求字幕轨同时满足 `Default && Forced`，
  而普通内封字幕是 `Default=true / forced=false` —— 于是「字幕：自动」等于**没有字幕**，
  用户以为这个文件压根没内封字幕。现在的顺序是：
  **显式指定 > 语言偏好命中（优先非强制轨）> 文件默认轨 > 无**。
  语言做归一（`chi`/`zho` ↔ `zh-CN`），所以浏览器给 `zh-CN` 也能命中 `chi` 轨。
- **中途续播 / 拖动之后，字幕整条错位。** 转封装播放的时间轴是**窗口相对**的
  （`seekable` 从 0 起），而字幕文件是**绝对**时间轴。浏览器原生渲染是按
  `video.currentTime` 匹配字幕的 —— 只要起播位置不是 0，字幕就整体偏一个窗口起点
  （实测偏了 235 秒：画面在演第 6 分钟，字幕显示第 170 秒的那句）。
  现在字幕层由我们自己按绝对时间挑条目显示，`<track>` 只用来读数据。
- **选了字幕但还没抽好时不再硬播。** 内封字幕要现抽成 WebVTT（4K / 网络盘上第一次
  可能要几十秒）。以前这段时间是**没有字幕**地放，用户以为选错了；现在显示
  「字幕正在准备…」，抽好自动开播。**自动选中的不拦**（不挡片子）。

## 二、新功能：设置 → 关于（检查更新）

- 新增 `GET /api/v1/update`（管理员），界面上是「设置 → 关于」的**检查更新**按钮。
- **由服务端去查**，不是浏览器直接打 GitHub：这个服务的设计是「HTTP 是唯一出口、
  服务端是唯一联网方」，看片人浏览器在什么网络环境不该决定服务端能不能检查更新；
  而且服务端查得出原因、结果能缓存。
- **默认不自动查**：只有点了按钮才出网 —— 没有外网出口的机器不会因为打开设置页就刷失败日志。
- 连点 **10 分钟内**直接回缓存（`cached: true`），保护上游的匿名限流（GitHub 是 60 次/小时/IP）。
- **查不成也是 HTTP 200**：`{ok:false, error:"人话原因"}`（网络不通 / 超时 / 上游格式不对），
  而不是统一错误格式 —— 请求本身合法，只是没查成。
- 更新源可配：`config.toml` 的 `[update] source_url`（留空 = 关闭，界面会说明不做检查）、
  `timeout_seconds`（默认 8）。
- 开发构建（`dev-xxxx`）不参与版本比较，只展示最新发布。

## 五、升级

- **v1.0.0 → v1.0.1 不需要任何手工步骤**：装上二进制重启即可（本版无新增迁移）。
- 想要「检查更新」可用，需要服务端能访问 `[update] source_url`（默认是 GitHub 的
  latest release 接口）；连不上不影响其他功能，界面会显示原因。
- 升级前建议先跑一次 `lmby backup`。

## 六、已知限制（本版未改）

- 字幕抽取失败时，播放页只会提示一次、不再自动重试；关掉字幕或重进页面可恢复。
- 其余限制与 v1.0.0 相同（Safari / iOS 未真机验证、直播无回看与 EPG、无内置 TLS 等），
  见 [`v1.0.0.md`](v1.0.0.md) 的「已知限制」。
