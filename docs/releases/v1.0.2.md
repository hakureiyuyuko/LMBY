# LMBY v1.0.2 —— 网络盘掉线不再清空媒体库

两个都会「静默毁数据」的问题：一个是**共享掉线时扫描把整库当成消失**，
另一个是**一个坏文件名搞挂整个扫描**。都修在这版。

> 补丁版，无破坏性改动：HTTP 接口、配置文件键、数据库迁移都向前兼容。
> 本版**没有新增迁移**（schemaVersion 仍是 18），装上二进制重启即可。
> 新增一个可选配置键 `[scan] max_delete_ratio`（不写也行，用默认值）。

---

## 一、网络盘 / 共享掉线，不再把整库删掉

**症状**（实测）：SMB 共享掉线的那次定时扫描，每个库根只报一条
`访问失败: lstat /mnt/media/…: host is down`，扫到 0 个文件，然后走删除步骤把
**整库 38437 个文件标记为删除**，而扫描状态还写着「成功」。

更麻烦的是它**自愈不了**：之后每次重扫，文件明明在磁盘上，但增量比对的输入只包含
「活着的行」，于是它们被当成新文件去插入 —— 而路径上的唯一约束还被那条已删除的行占着，
只好报一条「该路径已被其它条目占用，已跳过」。文件永远回不来，每轮重扫还多报一批
（实测库里 38461 个文件被这么钉死）。

**修法：三道护栏**

1. **读不到的目录，一律不参与删除判定。** 遍历时报错的位置（掉线的挂载点、掉权限的
   子目录）会被记下来，它下面的文件本轮不判「消失」。全部根都读不到时，这次扫描
   **判失败**并写明「本次没有删除任何文件」—— 报成功比删文件更误导人。
2. **比例闸 `[scan] max_delete_ratio`（默认 0.2）。** 有些掉线形态不报错（挂载点还在、
   目录读成空的），只能靠这一道：一次扫描要删的文件超过存活文件的两成就**一个都不删**，
   并判失败、把原因写出来。小库有豁免（不到 20 个文件的库按比例卡会把正常删除也拦下）；
   真要删掉大部分文件（比如换了媒体目录）把它设成负数即可。
3. **同一路径回来就复活。** 已删除的行现在也参与比对，路径再次出现时清掉删除标记、
   更新指纹（内容变了就重新排队读取流信息），而不是当新文件插入。

**已经踩到这个坑的实例怎么恢复**：升级后**手动重扫一次**那个库即可 —— 磁盘上还在的文件
会被逐个复活（这正是护栏 3 的作用）。扫描记录里新增三项：`复活`、`跳过删除`、
`读不到的根路径`（后两项非零时标红），失败原因直接写在扫描的「错误」里。

## 二、文件名不是合法 UTF-8，不再搞挂整个扫描

**症状**：扫描最后一步写「扫描问题」失败，整轮扫描被判失败：

```
写入扫描问题失败: ERROR: invalid byte sequence for encoding "UTF8": 0xde 0x20 (SQLSTATE 22021)
```

库是 UTF-8 的 PostgreSQL，而**文本有两个来路会带非法字节**：

- **文件系统**：SMB / 网盘共享上的文件名不保证是 UTF-8（挂载用 `iocharset=utf8` 时是
  原样透传字节的）；
- **按字节截断**：`s[:n]` 会把多字节字符从中间切开 —— 日志里实证过
  `标记探测失败失败: … 0xe3 0x80 0xe2`（被切开的汉字 + 补上的省略号）。

坏的不只是那一个文件：**扫描问题是整批写入的**，一条坏路径就让整批失败、后面几百条
问题全丢（实测只留下失败前写进去的 63 条）；库里的文件也会因此插不进来，
而界面上只会看到「已被其它条目占用」这种看不懂的话。

**修法**

- 新增内部工具包统一处理：**rune 边界截断**（不再有手写的 `s[:n]`，涉及 ffprobe 输出、
  探测失败原因、User-Agent、直播源状态、TMDB 响应体、硬件能力探测）+
  **入库前把非法字节换成 `�`**（最坏情况是那一条的坏字节显示不出来，而不是整批失败）。
  User-Agent 那处尤其值得一提：切坏了会让会话写不进库、**登录直接失败**。
- 扫描器遇到名字不是合法 UTF-8 的条目（文件或目录）直接跳过，并记一条问题，
  说明里带坏字节的十六进制，照着改名后重扫即可入库 —— 而不是让它拖垮整轮扫描。
- 「写入扫描问题失败」这类错误现在会带上**第几条 + 路径**，不用再猜是哪一条。
- 顺手修掉失败记录里的「**耗时 0.0 秒 / 问题 0**」：这两个统计原本在写问题清单之后才
  赋值，而那一步失败就提前返回了，界面上于是出现「失败 + 耗时 0 秒 + 列出 63 条问题」
  这种自相矛盾的记录。

## 三、发布流程

- 修掉发布脚本的一个真问题：第二次以后发版时，交付版 README 的源文件会因为合并判定
  （`docs/README.release.md` 被算成删除）而取不到，脚本会「跳过」—— 结果是**交付分支上
  放了一份开发者 README**。现在脚本会直接从开发分支取源文件。

## 五、升级

- **v1.0.1 → v1.0.2 不需要任何手工步骤**：装上二进制重启即可（本版无新增迁移）。
- 如果你遇到过「某个媒体库突然变空 / 扫描问题里全是『已被其它条目占用』」：
  升级后**手动重扫一次那个库**，文件会被复活。
- 想调整删除保护：`[scan] max_delete_ratio`（默认 `0.2`；`0` = 用默认值，
  负数 = 不限制）。配置样例见 `deploy/lmby.example.toml`。

## 六、已知限制（本版未修）

- **同一部作品可能出现两张同名海报**：条目的身份键里包含年份，而年份会被同目录的
  nfo（或刮削结果）覆盖成另一个值，下次扫描就认不出自己的条目、又建一个。
  下一版修（涉及条目身份判定，要单独验）。
- 其余限制与 v1.0.0 / v1.0.1 相同（Safari / iOS 未真机验证、直播无回看与 EPG、
  无内置 TLS 等），见 [`v1.0.0.md`](v1.0.0.md) 的「已知限制」。
