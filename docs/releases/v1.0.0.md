# LMBY v1.0.0 —— 第一个正式版

LMBY 是**纯 Web 在线播放**的轻量自托管媒体服务器：浏览器是唯一客户端，HTTP 是唯一出口，
一个 Go 二进制（前端 `go:embed` 进去）+ PostgreSQL，**运行期零 Node**，AGPL-3.0。

> **1.0 的含义：从这一版起承诺稳定。** 往后版本保持 HTTP 接口、配置文件键与数据库迁移的
> 前后兼容（迁移只做增量、不重命名既有键；修 bug 走补丁版本）。0.x 期间那些还在移位的东西
> ——界面文案、目录布局、验收脚手架——到这一版为止。

## 一、相比 v0.9.0 的变化

v0.9.0 已经收拾好了**交付面**（界面去解释性文字、仓库不带开发过程文档）。v1.0.0 在它之上
把**管理面补齐**，并补上机器接口。

### 设置页补齐（11 个页签）

元数据与服务状态、**转码与硬件**、**日志**、库管理、**扫描计划**、人工匹配、会话、直播源、
用户、**审计日志**、**缓存与清理**。

- **转码与硬件**：本机编码能力（后端 / 设备 / 编码 / 解码 / 实测倍速）与失败记录，
  一键重新探测。能力来自**真跑探测** —— `ffmpeg -encoders` 里列着不等于这台机器能用它。
- **日志**：服务端最近日志（内存环形缓冲，2000 条），按级别 / 关键字筛选、下载当前视图。
- **扫描计划**：每个媒体库各自的自动扫描间隔（0 = 不自动，上限一周）；改完立即生效。
- **审计日志**：谁在什么时候做了什么 —— 登录、改口令、用户与媒体库的增删改、手动扫描、
  修改设置；可按动作 / 关键字筛选、只看失败。**口令与密钥不会出现在这里。**
- **缓存与清理**：图片缓存 / 转码分片 / 探测目录 / 叠加层与孤儿的占用；
  可清图片缓存与孤儿 —— **绝不碰媒体文件，也不碰还在库里的数据**。

### 用户与权限

- 库级可见性白名单；`允许转码` / `允许直播` / 并发播放上限；入口在「设置 → 用户」。
- 三条硬规则：**不能改自己的管理员位与禁用位**；不能让**最后一个管理员**被禁用 / 降级 / 删除；
  改口令 / 禁用 / 收紧库范围会**立刻吊销该用户的全部会话**（否则旧会话还能照旧看片）。

### 备份与恢复

新增 `lmby backup` / `lmby restore`：

```bash
lmby backup  -o lmby-$(date +%F).tar.gz [--with-overlay]
lmby restore -i lmby-2026-09-23.tar.gz --yes [--dsn DSN] [--data-dir 目录] [--overwrite-config]
```

- 备份 = 数据库（`pg_dump -Fc`）+ `config.toml` + `secret.key`；**不含缓存**
  （图片缓存、转码分片、探测目录都能重新生成）。
- 恢复会 `pg_restore --clean` **清空目标库**，所以必须显式 `--yes`；
  已存在的 `config.toml` / `secret.key` **默认不覆盖**；日志里的 DSN 做遮罩；解包拒绝 `../`。

### 给 bot / 脚本的用户管理接口

- 一把长期密钥（`Authorization: Bearer <key>` 或 `X-API-Key: <key>`），
  **只在用户管理那 7 个路径生效**，其余接口一律 403；明文只在生成时显示一次，库里只存 SHA-256。
- 密钥做的每次操作都进审计，操作者记为 `api-token`。
- 面向使用者的说明见 [`docs/BOT-API.md`](BOT-API.md)。

### 文档

- 新增 [`docs/API.md`](API.md)：**完整的 HTTP 接口参考** —— 认证方式、统一错误格式、
  逐条端点的参数 / 请求体 / 响应、枚举与时长单位（ticks）约定。

### 稳定性与质量

- 修掉 `golangci-lint` 报出的 13 项（11 处 `errcheck`、1 处 `unparam`、1 处死代码）
  与两处 `gofmt` 偏差 —— 这一批代码此前 CI 的 lint 任务是红的。
- 发版前的**全站页面巡检**扩展到 25 个页面（含全部设置页签、列表详情、条目编辑、404）。

## 二、修掉的问题

- **审计只记了一半**：`detail` 为空时按 SQL `NULL` 写入，违反 `not null` 而失败 ——
  又因为审计失败刻意只 Warn，表现为「审计里少记录」而不是报错。已改为空对象。
- **用管理密钥请求一律 401**：鉴权中间件强制要 Cookie，不认已经注入的登录态。已改为先看 context。
- **首页整页 500**：可见库条件的参数占位符错位（PG `42P18`）——与账号无关，管理员同样 500。
- **搜索对所有人返回 0 条**：可见库参数被绑成 `NULL` → `cardinality(NULL)` 恒不成立；
  接口回 200 + `total: 0`，只看状态码的验收看不见。顺带修掉「白名单开着但一个库都没勾」
  被当成「不过滤」的权限隐患。
- **新建 / 列出媒体库 500**：手写的 `Scan` 在表加列后列数不匹配，已统一到 `scanLibrary()`。
- **管理面「会话」页直播会话永远为空**：解析会话键时没跟上「转封装 / 转码各自一路」的格式，
  那条记录被静默跳过（不报错，不影响播放）。
- **直播起播 502 的排查**：确认不是代码问题 —— 那条频道在库里本就是失效源
  （`probe_ok=false`），前台按设计不显示它。

## 四、已知限制

- **Safari / iOS**：原生 HLS / HEVC / WebVTT 的旁路代码就位，但**没有真机验证**。
- **直播**：失效源按探测快照判定（起播失败会自动重探一次，但源站变坏总要先失败一次才被发现）；
  没有回看 / 时移，没有 EPG / 录制。
- **外链分享**：只做给外部播放器的**直播**签名地址；**媒体库内容不提供公开分享链接**
  （这是有意为之：多一条公开访问路径就多一块攻击面，要分享请用现有账号体系或自己加反向代理）。
- **管理密钥**只为用户管理接口而存在，不能用来改设置 / 删媒体库 / 读别人的库内容；
  需要更大权限请给它一个真正的管理员账号。
- **家长分级**、个人中心的字幕与音轨偏好、弹幕、海报墙虚拟滚动与批量入列表、
  Jellyfin API 兼容层：都尚未做（1.0 之后）。
- 1 秒分片让请求数翻倍，弱网下表现未测。
- 没有内置 TLS：要给家庭网络之外访问请自己加反向代理。
- Windows / macOS 上转码不节流（无法暂停进程，优雅降级为「不节流」）。

## 五、升级

- 数据库迁移是**增量**的（本版新增 `0016_users_permissions` / `0017_library_scan_schedule` /
  `0018_audit_logs`），启动时按 `LMBY_AUTO_MIGRATE`（默认开）自动应用。
- **v0.9.0 → v1.0.0 不需要任何手工步骤**：装上二进制重启即可。
- 建议升级前先 `lmby backup`（见上）。

## 六、快速开始

需要 PostgreSQL 与服务端 `ffmpeg` / `ffprobe`；配置放 `/etc/lmby/config.toml`，
systemd 单元与示例配置见 `deploy/`。Docker 方式与手动部署步骤见 `README.md`。

> 数据库必须是 **UTF8 编码 + UTF-8 的 `lc_ctype`**（如 `C.UTF-8`）。建错了 LMBY 会在启动时
> 直接拦下并给出修法 —— 那种库里中文会退化成字节，中文搜索与模糊匹配会静默失效。

**Assets**：`lmby-linux-amd64` / `lmby-linux-arm64` / `lmby-linux-armv7` / `lmby-windows-amd64.exe`，
以及 `SHA256SUMS.txt`（`sha256sum -c SHA256SUMS.txt` 校验）。

逐版说明见 [`CHANGELOG.md`](../CHANGELOG.md)。
