# LMBY v1.1.1 —— Go 标准库 CVE 修复

本版是一次**安全更新**：改用 Go 1.27.4 构建，修掉标准库里已公开的 **12 个 CVE**
（均自 Go 1.27.2 起修复）。

> 这是**构建层面的修复**：没有行为变化、没有数据库迁移、没有配置改动。
> 升级方式与往常一样：换二进制、重启即可。

---

## 一、修复的漏洞

全部位于 Go 标准库（`net/http`、`crypto/x509`、`crypto/tls`、`net/textproto`）：

| ID | 包 | 问题 |
|---|---|---|
| GO-2026-6859 | net/http | HTTP/1 `MaxBytesReader` 头竞争导致服务崩溃 |
| GO-2026-6809 | crypto/x509 | 未拒绝受损的中间证书 |
| GO-2026-6617 | net/http | HTTP/2 HPACK 编码器竞争导致崩溃 |
| GO-2026-6613 | net/http | HTTP/1 收到 2xx CONNECT 响应后连接不同步 |
| GO-2026-6612 | net/http | HTTP/2 服务端流上的双流控退款 |
| GO-2026-6611 | net/http | 重复 initial window 变更导致 CPU 过度消耗 |
| GO-2026-6610 | net/http | HTTP/2 transport 接受畸形的 framing 相关头 |
| GO-2026-6609 | net/http | 解析 `Range` 头时没有大小上限 |
| GO-2026-6608 | net/textproto | 解析 MIME 头时可绕过内存限制 |
| GO-2026-6607 | crypto/tls | 未拒绝畸形的 ECH outer extension 引用 |
| GO-2026-6605 | net/http | HTTP/1 CONNECT 被拒后客户端连接不同步 |
| GO-2026-6603 | net/http | HTTP/2 的 Trailer 头导致服务端内存耗尽 |

其中多数与 **HTTP 服务端/客户端** 有关（LMBY 既对外提供 HTTP 服务，也主动出网抓取元数据与直播源，
两边都受影响），因此建议所有用户升级。

另外把 `golang.org/x/crypto` 升到 v0.58.0（连带 `x/sync`、`x/sys`、`x/text`）。

## 二、验证

| 项 | 结果 |
|---|---|
| `govulncheck ./...`（Go 1.27.4） | **0 个漏洞**（修复前：12 个，全部来自标准库） |
| `go build ./...` / `go vet ./...` | 通过 |
| `go test ./...` | 全部通过 |
| 前端构建 / i18n 覆盖率 | 通过 / 100% |

> 说明：`govulncheck` 仍会提示一条 `golang.org/x/crypto` 的 `openpgp` 模块级问题
> （GO-2026-5932）。该包**没有被调用**，且其修复版本目前仍是伪版本，故未追。

## 三、顺带的小改动

- **媒体库可以改名了**：设置 → 库管理 → 编辑里多了「名称」。改名只换显示名，
  条目的归属不变（`library_id` 不动）。
- 「元数据刮削」的提示不再只提 TMDB：现在写明 **TMDB 或 KeqDB 任选一个**即可开始刮削。
